# Apple→Plate pretrained encoder v1: results (TASK-063)

**Outcome O-PT-POOLED.** The protocol (§11) defines this row as: P-cls passes. **The abandonment
clause does not fire.**

- **Both decisional arms pass**, each against a random-init encoder of the same architecture read
  at the same point:
  - **P-cls**, the frozen DINOv2 ViT-S/14 CLS token (384-d), reads the post-look apple to
    0.538 cm, with the dx sign right on 183/190 roots.
  - **P-tok**, the same encoder's 256 final patch tokens, reads it to 0.394 cm, with 187/190.
- Each arm meets every TASK-059 bar, beats its floor, is rejected by Holm over the two arms, and
  passes the apple-hidden check.
- P-tok also passes. The first matching row is O-PT-POOLED, so O-PT-TOKENS is not the outcome.
  - The report lists O-PT-TOKENS under `also_matching_rows`.

## 5. Reading (interpretation, not measurement)

1. **An externally pretrained frozen encoder exposes the post-look apple in its pooled feature,
   beyond its random init.**
   - P-cls reads the apple to 0.538 cm with 183/190 dx signs.
   - It beats R-cls by 0.316 cm [0.214, 0.456] and 14 roots on the sign.
   - It is not detectably different from raw pixels: P-cls − L-raw is +0.068 cm [−0.010, 0.153]. No equivalence margin
     was preregistered, so this is not a claim of equivalence.
   - This is what TASK-062's in-corpus encoders did not achieve: R0-cls there read 1.223 cm,
     and P-cls − L-E0 here is −0.735 cm.
2. **The tokens read it best of any source on this probe.**
   - P-tok is 0.394 cm with 187/190, and it is below raw pixels: −0.075 cm [−0.142, −0.007].
   - Its margin over its own floor is smaller: −0.106 cm [−0.182, −0.041]. This fits TASK-062's
     finding that random ViT tokens already carry the apple (F-tok; here also R-tok, 0.500 cm).
3. **Why this encoder works and TASK-062's did not is not identified** (protocol §3.2, stated in
   advance). The pretraining data, the width (384 against 128) and the input size (224 against
   112 px) all changed at once. Two observations bear on this, and neither isolates a cause:
   - the random init of *this* architecture already reads the apple from its pooled feature
     (R-cls meets the bars; L-random did not);
   - the pretrained CLS is clearly better than that.
4. **What this does not show.**
   - Whether a world model built on this encoder keeps the apple through prediction.
   - Whether a controller could use it.
   - Anything closed-loop.
   - Floor-seed variance: there is one floor seed.
   - Other pretrained encoders. Only one was tested.

## 7. Caveats kept in the record

- **One encoder, one input size, one floor seed.** Floor-seed variance is not measured. With
  P-tok's margin over R-tok at −0.106 cm [−0.182, −0.041], a different floor seed could move it.
- **The T2 McNemar tests against the floors are not all significant.** P-tok's is 8 / 2,
  p = 0.109. The preregistered floor rule compares point accuracies, and it was met.
- **Arm state is decided per encoder.** Had either encoder produced a non-finite feature, both
  arms would have been "not evaluated". This is the runner's reading of "the arm's or its floor's
  featurisation" (PR #62 review, item 6). It did not arise: there were no non-finite features.
- **Reported-only code could still have voided the run after the decision.** That code is the
  calibration-renderer frame check, inherited from TASK-062, and the label-free featurisation. It
  did not happen.
- **The Wilson intervals assume independence only approximately.** The out-of-fold predictions
  come from ten readouts, as in TASK-059, TASK-061 and TASK-062.
- **Kernel-ridge values are not bit-reproducible across machines** (BLAS). The run used the
  machine TASK-061 and TASK-062 ran on, and both anchor sets reproduced exactly.
- **The weights were released in 2023 from web images** (LVD-142M, not released). Their exact
  training contents cannot be audited. No robot imagery is disclosed (protocol §4.4).
